NAZZTEC — WordPress Build Spec

A custom-coded WordPress theme built directly from whichever homepage concept the client selects (Demo 1, 2, or 3) — the existing HTML/CSS/JS drops into PHP templates largely as-is, with Advanced Custom Fields (ACF) powering the dynamic content. This is the construction spec for that build; treat the chosen demo's HTML file as the visual and content source of truth.

Overview

All three demos share identical content structure (hero, global presence, 8-domain capability index, staffing, why-NAZZTEC, frameworks, digital transformation, engagement models, industries, CTA, footer) — only the visual system differs. That means this spec applies unchanged regardless of which demo the client picks; only the CSS file and a handful of icon/markup details change.

Why custom-coded, not a page builder — the demos are already fully-built static HTML/CSS/JS with no framework dependency. Converting that directly into PHP templates is faster and pixel-exact. The trade-off: content edits go through WordPress admin forms (ACF fields), not a visual drag-and-drop canvas. Confirm that's acceptable to the client before starting.

Theme File Structure

A classic (non-block) custom theme, since the source is hand-written HTML/CSS/JS rather than Gutenberg blocks.

/wp-content/themes/nazztec/ style.css theme header comment + the demo's CSS, ported in functions.php enqueue assets, register CPTs/menus, ACF options page header.php <head>, opening <body>, site nav (from the demo's <header>) footer.php footer markup + closing tags + wp_footer() front-page.php the homepage — loops the ACF/CPT data into the demo's sections page-staffing.php Staff Augmentation page template page-about.php About Us page template page-contact.php Contact page template (form embed) single-service.php Service detail template (one per capability) archive-insights.php Insights index single-insight.php Insight article template template-parts/ section-hero.php section-flagship.php section-presence.php section-services.php section-staffing.php section-why.php section-frameworks.php section-digital.php section-engagement.php section-industries.php section-cta.php assets/ css/main.css the demo's <style> block, extracted js/main.js the demo's <script> block, extracted images/
Splitting the homepage into template-parts/section-*.php (one file per section) makes it trivial to reuse sections across pages later, and keeps front-page.php to a short list of get_template_part() calls.

Asset Pipeline

The demo files are single self-contained HTML documents with inline <style> and <script>. Extract them once, then enqueue properly — never leave inline blocks in the theme.

  1. 01 Copy everything between <style>/</style> from the chosen demo into assets/css/main.css verbatim.
  2. 02 Copy everything between <script>/</script> into assets/js/main.js verbatim.
  3. 03 Register both in functions.php using wp_enqueue_style / wp_enqueue_script — see snippet below.
  4. 04 Keep the Google Fonts <link> tags in header.php's <head> exactly as in the source demo.
// functions.php function nazztec_enqueue_assets() { wp_enqueue_style( 'nazztec-main', get_template_directory_uri() . '/assets/css/main.css', [], '1.0.0' ); wp_enqueue_script( 'nazztec-main', get_template_directory_uri() . '/assets/js/main.js', [], '1.0.0', true ); } add_action( 'wp_enqueue_scripts', 'nazztec_enqueue_assets' );
The JS is already framework-free vanilla (IntersectionObserver reveals, scroll-spy, canvas animations, mousemove tilt) — it needs zero rewriting to run inside WordPress, since it only queries DOM elements by class/ID that the PHP templates will still output identically.

SEO, Performance & Security

  • Set meta title/description per page via Yoast/RankMath — pre-fill from each service's hero_text field for service detail pages.
  • Generate an XML sitemap (Yoast/RankMath handle this automatically) and submit to Google Search Console at launch.
  • Lazy-load the hero and section photography; the existing CSS already avoids layout-shift-prone patterns.
  • Enable page caching but exclude the Contact/forms pages from full-page cache to avoid stale nonce issues.
  • Force HTTPS, enable a Web Application Firewall (Wordfence/Sucuri), and disable XML-RPC if unused.
  • Set up automated daily backups with at least 14-day retention, stored off-server.

Build Order

  1. 01 Provision hosting, install WordPress, install ACF Pro + the plugin stack above
  2. 02 Scaffold the theme (style.css header, functions.php, blank templates)
  3. 03 Extract CSS/JS from the chosen demo into assets/ and enqueue them
  4. 04 Register the service and location CPTs, the insight_category taxonomy, and the ACF field groups + Options Page
  5. 05 Build header.php / footer.php first — every page depends on them
  6. 06 Enter real content into the CMS (start with service — it's the load-bearing content type)
  7. 07 Build front-page.php section by section, wiring each template-parts/section-*.php to its data source per the mapping table above
  8. 08 Build single-service.php, then the static pages (Staffing, About, Contact)
  9. 09 Wire up WPForms and confirm email delivery for all three forms
  10. 10 Responsive QA at 1440 / 991 / 767 / 479px; confirm the JS interactions (reveals, scroll-spy, tilt) still fire correctly inside WP's markup
  11. 11 Run SEO/performance/security setup from the section above
  12. 12 Push to staging for client review, then cut DNS over at go-live
